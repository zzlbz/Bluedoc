# BlueDoc V0.3.1 验证记录

日期：2026-10-04。这是 V0.3 的分类数据层补丁，兼容 Typecho 1.3.0 / PHP 8.2。实测环境为隔离 Typecho 1.3.0、PHP 8.2.29、SQLite 和内置浏览器。

## 变更行为

- 四个设备槽位保持 Windows、Android、iOS、macOS。配置字段仍为 bluedocQuickWindowsMid / AndroidMid / IosMid / MacosMid，不迁移已有设置。
- 标题与描述来自配置 MID 的真实分类；描述为空时不生成固定介绍。标题进入分类概览，教程列表进入真实文章。
- 每张卡片展示其分类及所有后代分类最新三篇公开文章，按 created 倒序、同时间按 CID 倒序，从公开索引筛选并去重。草稿、私密、未来文章不进入索引。
- 明确填写但不存在的 MID 显示准备中且没有教程或分类链接。只有 MID 留空才使用原有平台自动发现规则。
- 分类概览显示返回父分类入口、子分类卡片和本分支全部公开文档，包含所有后代并去重；列表只显示文章标题和分类。
- 当前文章/分类的侧栏仅显示其关联顶级根分支。多分类文章保留全部关联根分支，按后台顺序；祖先展开、当前高亮和面包屑维持原生分类关系。未归类文章显示提示，独立页面保留全树。
- 无第三方插件，不修改核心或站点分类。复用请求内批量索引，不增加逐设备 SQL 查询。

## 复测

```sh
php tests/navigation.php
node --check theme/assets/js/main.js
node --check tests/typecho-smoke.mjs
node tests/typecho-smoke.mjs
```

HTTP 默认地址 http://127.0.0.1:18230/，可设置 BLUEDOC_BASE_URL。先在测试站启用 0.3.1，建立客户端教程及四个平台分类，并在主题设置填写实际 MID。HTTP 脚本只读，不登录、不修改数据。

测试以下内容：

1. 在平台及更深子分类分别发布多篇教程，确认卡片只选本分支最新三篇；多分类关联只出现一次。
2. 创建草稿、私密、定时文章和密码文档，确认候选过滤和原生密码保护。
3. 修改分类名称/描述，确认按 MID 的卡片立即跟随；删除配置分类，确认没有自动转到别的同名分类。留空 MID 时复查自动平台发现。
4. 从卡片进入教程，检查面包屑、所属顶级分支、同类文章、当前高亮和祖先展开；多分类文章检查所有关联根分支。
5. 从文章返回分类及父分类，检查子分类卡片和整个分支的文章列表；检查手机抽屉与页面宽度。
