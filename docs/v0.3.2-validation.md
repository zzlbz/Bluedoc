## 数据逻辑

分类名称和 slug 不参与行业判断。默认快速导航读取 `children[0]` 前四项；选择父分类后读取 `children[mid]` 前四项，保留后台排序。卡片标题、简介和 permalink 来自分类节点，最新三篇文档复用公开索引，包含后代分类、按创建时间/CID 倒序并去重。全部分类模块显示所有真实一级分类及直接子分类，不补占位分类。

父分类删除后恢复默认一级分类范围；有效父分类无子分类时显示空状态。旧版平台设置不再使用，标题、描述和精选 CID 字段保留。原生多级树、面包屑、文章权限和正文输出继续沿用现有实现。

## 复现

1. 在隔离 Typecho 1.3.0 / PHP 8.2 站点完整安装 `theme/` 并启用 BlueDoc 0.3.2。
2. 建立任意一级、二级、三级分类，调整后台排序，发布分别关联这些分类的文档，并保留真实空分类。不要依赖特定设备名称。
3. 默认首页快速导航应是前四个一级分类；全部分类应与实际一级分类完全一致。改名、排序、发布文档后刷新验证。
4. 在“设置外观 → 快速导航分类范围”选择有子分类的父分类，核对入口、简介、最新三篇文档。再选择无子分类的分类，验证空状态；全部分类仍可访问。
5. 用草稿、私密、未来及密码文档验证权限；检查文章所属分支、祖先展开、面包屑、H2/H3 目录和手机抽屉。
6. 在仓库运行以下检查。无实际分类或文档时，HTTP 脚本明确跳过相应路由。

```sh
php tests/navigation.php
node --check theme/assets/js/main.js
node --check tests/typecho-smoke.mjs
node tests/typecho-smoke.mjs
```

全量 PHP 语法检查：

```powershell
Get-ChildItem theme -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
php -l tests/navigation.php
```

测试账号、数据库、核心、运行时和临时数据脚本均不属于主题发行文件。
