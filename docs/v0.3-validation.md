## 复现方法

1. 准备隔离的 Typecho 1.3.0 与 PHP 8.2，配置站点 URL，复制 theme/ 内文件到 usr/themes/BlueDoc/ 并启用。确认后台版本和 HTML bluedoc-version 都是 0.3.0。
2. 建立六个一级分类，客户端教程下建立四个平台，再建立 v2rayN 等多级子分类；在每级放置测试文章，包括多分类文章、草稿、私密、未来发布时间和密码文档。后台调整分类顺序后检查首页和树顺序。
3. 在项目根目录运行：

```sh
php tests/navigation.php
node --check theme/assets/js/main.js
node tests/typecho-smoke.mjs
```

HTTP 脚本默认读取 http://127.0.0.1:18230/，不登录、不改数据。可指定测试站：

```powershell
$env:BLUEDOC_BASE_URL = 'http://127.0.0.1:18230/'
node tests/typecho-smoke.mjs
Get-ChildItem theme -Filter '*.php' -Recurse | ForEach-Object { php -l $_.FullName }
php -l tests/navigation.php
```

没有平台分类或公开文章时，HTTP 脚本会跳过相应路由检查；验收完整功能前应准备这些内容。

4. 原生后台依次保存默认设置、热门 CID（重复/不存在/草稿）、macOS MID、带 < 和 & 的首页文案，再提交非法 CID/MID，确认校验拒绝且之前有效值保持。V0.2 三个平台 MID 和热门 CID 字段名称不变。
5. 打开文章验证祖先展开、当前位置、面包屑和 modified；建立至少十层子分类验证无固定深度上限。给文章添加同名 H2/H3、现有 ID 和重复 ID，检查目录不冲突。
6. 在 1024/1023/768/767/375px 查看目录、抽屉和页面宽度；用 Tab、Shift+Tab、Escape 和遮罩操作抽屉，并在开启时切换桌面宽度。检查 PHP 和浏览器日志。
7. 部署到真实站点前备份旧主题，只更新主题文件。确认实际启用的是新目录，清理缓存后检查版本标记和设备/分类/教程路径。现有站点的分类整理、插件及固定链接应在其环境复查。

完整源生后台与深层 fixture 验证脚本使用本次临时测试站，不作为依赖发布。仓库提供可独立运行的逻辑检查与只读 HTTP 冒烟。
